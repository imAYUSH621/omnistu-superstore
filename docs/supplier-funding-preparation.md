# Supplier funding preparation, still OFF

This extends the real Store admin order page. For a paid, exact supplier-bound, non-simulated order, the admin sees the supplier funding review separately from customer payment. The action is independently gated by `CJ_FUNDING_PREPARATION_ENABLED` (default OFF). No funding executor, approval writer, balance top-up, cancellation, replacement order or customer message is added. Existing delivery control is relabeled to check supplier delivery rather than pretend an admin click establishes arrival.

The documented sequence for a newly created payType3 order includes addCart, addCartConfirm, then saveGenerateParentOrder. These are account mutations, not harmless price lookups. They must not be enabled or invoked without separately approved owner scope. The action validates the persisted paid exact plan, consumed allocation and accepted supplier ID, re-reads the provider identity/products/address/origin/method, and refuses missing postal evidence. It cannot add a different order, warehouse or packaging. Parent quotes with interception, unmatched lines, substituted order sets, missing monetary fields or conflicting final totals are refused. No request to proceed past an intercepted order is implemented.

A single per-order durable claim is written before the first mutation. CART_UNKNOWN, CONFIRM_UNKNOWN and PARENT_UNKNOWN checkpoints are committed before their corresponding provider call. A lost or invalid response leaves that state and never causes an automatic retry. Successful review-only evidence is returned from storage on repeat without another provider call. Concurrent requests cannot duplicate any of the three account mutations. The database rejects binding rewrites, state rollback, evidence deletion and insertion directly into REVIEW_ONLY. No approval is represented by any state or environment flag.

The admin view shows the provider's exact payable total and separate source fee fields without summing overlapping fields. Its expiry is preserved as text, not assigned a guessed timezone. A saved quote does not mean it remains valid or that any payment has occurred. No Pay button is provided. The final payment method, final payable amount, full recipient/order set, expiry timezone, cancellation cost and owner authority must be verified before any real supplier payment. Agent execution must use a supported payment route; this change does not authorize a direct balance-wallet API payment.

## Still unresolved

- CJ's published order detail schema omits postal code. Tests explicitly supply it; they do not establish live provider compatibility. Missing exact destination evidence fails before an account mutation, shipment or delivery write.
- The parent-order documentation shows payExpireTime without a timezone, and does not fully define every successOrders identifier mapping. Strict matching may refuse legitimate responses until authoritative evidence resolves those contracts. Do not loosen them from example guesses.
- No live provider points, orders, confirmations, payment parents or money were used in qualification. All provider responses were synthetic. No merchant KYC, current stock/freight/handling, live payment receiving, retail price/customer policy or commercial-hosting decision is inferred from these tests.
- A payment executor is deliberately absent. Unknown outcomes need authoritative provider/account recovery, not a new attempt. The Store is not yet earning-ready.

Local typecheck and lint pass. All232 suites /2006 tests pass, zero skips, including24 connected disposable-PostgreSQL supplier tests. Added cases cover exact final fees, source-contract refusals, admin-only access, OFF/no fetch, real server action -> cart -> confirmation -> final review journal, repeat without fetch, lost responses at all three stages, missing postal refusal before mutation, and concurrent calls producing one mutation per stage.
