# Rank the catalog before limiting assistant matches

The database assistant path formerly fetched an arbitrary 25 matching rows, then scored that truncated pool. A stronger name match outside those rows could never appear. The existing Prisma SQL surface now scores the whole matching relation, filters positive scores, orders by score/name/slug and then limits to five. Fixed field weights are name 4, category 3, brand 2 and description 1 per distinct bounded term. This is deterministic lexical retrieval, not semantic embedding or generative RAG.

All search terms and hidden fixture/test-catalog prefixes remain bound parameters. Fixed column identifiers and SQL shape are not supplied by visitors. Literal percent/underscore characters are not LIKE wildcards. Original product names, prices, stock-zero note and links are formatted as before. No popularity/review data contributes. Existing available/unavailable envelope, public fixture hiding and test-catalog gate remain. No sample fallback on a failed configured DB read.

Local source/unit checks cover bound SQL, the single final row limit, guard values and unchanged formatted output. A read-only CTE on the existing PostgreSQL engine supplies 60 earlier weak description matches, three stronger/tied later name matches and three excluded test-prefix matches: the expected strongest/tie ordering and final five are verified without saving rows. This is actual SQL engine proof over synthetic values, not a persisted catalog or hosted large-catalog load test. Same-source hosted public empty and existing isolated Testshirt positive API/UI proof are separate. No product rows, reviews, accounts or orders are created.
